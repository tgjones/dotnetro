# Irie (compiler backend) notes

Loaded when working under `src/Irie`.


- **Irie** — the compiler backend: unified MIR + MachineCode layers, the pass pipeline and the MOS6502 target. `DotNetro.Compiler` depends on it; it is also usable standalone via the `iriec` / `irie-*` tools
  - `Mir/` — single unified MIR layer; one IR flows through every pass, with only the opcode mix and the level of physreg / class detail evolving as passes run; `;` starts a line comment
    - `Mir/Parsing/MirParser` — text parser; two-pass within each function (scan block headers for `bbN(` first, then parse instructions) so branches can forward-reference blocks. Supports multi-def syntax `%a : i8, %b : i1 = some.op …`. `Mir/Writing/MirWriter` prints with `func @name : (…) -> T` header, vregs annotated at their def site (type pre-isel, class post-isel), and `[liveins: $a, $x]` lines on blocks with non-empty live-ins.
  - `Dialects/` — opcode definitions used in the MIR. Each dialect is one folder.
    - `Core` — `core.return` (source-level return, carried until ABI lowering).
    - `Arith` — pure SSA value producers: `arith.addi`, `arith.subi`, `arith.cmpi <pred>` (predicate from `ArithCmpPredicate`), `arith.addi_with_carry` (2 defs: result + carry_out; 3 uses: a, b, carry_in — the post-legalization narrow form of multi-byte add). Bitwise `arith.and`/`or`/`xor`; shifts `arith.shl`/`lshr`/`ashr` (constant amount only, lowered by the MOS6502 legalizer to byte moves plus chains of the target's pre-selection one-bit ops `mos6502.shle`/`lshre` — result + carry_out, carry_in; the analogues of llvm-mos `G_SHLE`/`G_LSHRE` — which select to `asl`/`rol`/`lsr`/`ror`.acc).
    - `Mem` — address and memory ops. `ptr` is a distinct, opaque 16-bit type (`PointerType`; no pointee — the value type lives on the load/store op), **not an integer**: no `arith.*` op takes or produces one. `mem.symbol @g` / `mem.frame_addr N` produce a `ptr`; `mem.ptradd %p, %off` (`(ptr, i16) -> ptr`, byte offset, no scaling) is address arithmetic; `mem.load.{i8,i16,i32,i64}` / `mem.store.*` / `mem.fill` take a `ptr` address, and `mem.load.ptr` / `mem.store.ptr` move a pointer-valued datum. `mem.load.byte_at` / `mem.store.byte_at` are the post-legalization byte forms.
    - `Cast` — `cast.trunc` / `zext` / `sext` between integers, and `cast.ptrtoint` / `cast.inttoptr` (`ptr` ↔ `i16`, same width only). A null pointer is `inttoptr (arith.constant 0)`; a pointer compare is `ptrtoint` both sides plus an integer `cmpi`. The IL front end treats native int (`IntPtr`, `conv.i`) as an `i16` integer and inserts these casts where IL uses one as an address.
    - `Cf` — terminators only: `cf.br`, `cf.cond_br`. Both use `BlockTarget` operands that may carry per-edge block arguments.
    - `Pseudo` — scaffolding ops lowered/expanded by later passes: `pseudo.copy` (universal copy — vreg→vreg pre-isel, mixed during isel, physreg→physreg post-RA, expanded to target moves last), `pseudo.merge` / `pseudo.unmerge` (artifact ops folded by the legalizer's artifact combiner), `pseudo.return` (void return shell emitted by ABI lowering; survives to isel where it is lowered to the target's return op).
  - `Passes/` — all generic passes plus pass infrastructure (`Pass`, `PassManager`, `CompilationContext`, `MirFunctionPass`, `MirFunctionAnalysis`). Pipeline order in `iriec` is (`ReturnMergePass` runs first, before `AbiLoweringPass`: when a function has ≥2 `core.return` blocks it merges them into one common return block — each return becomes `cf.br retblock(%v)` with the value as a block parameter — so the return epilogue is emitted once; the SimplifyCFG `tailMergeBlocksWithSimilarFunctionTerminators` analogue, merging unconditionally with no cost model. Where merging a *trivial* tail did not pay off, the post-RA generic `TailDuplicationPass` rebalances it back (see item 8) — same division of labour as llvm-mos's SimplifyCFG-merge + TailDuplicate):
    0. `GenericMirVerifierPass` — runs first: no inline value `Immediate`s, and the pointer typing rules above (address operands are `ptr`, `ptradd` is `(ptr, i16) -> ptr`, arith never sees a `ptr`), plus `call.func` arguments/results checked against the callee's signature when it is in the module.
    1. `AbiLoweringPass` — drops entry-block parameters; emits per-arg-byte `AddLiveIn(physreg)` + `pseudo.copy` from the physreg into a vreg, plus `pseudo.merge` for wide arg types. Rewrites `core.return %v` to per-byte `pseudo.unmerge` + `pseudo.copy` to return physregs + `pseudo.return`. Delegates the calling-convention details to `Target.CallLowering`.
    2. `LegalizerPass` — worklist-driven legalizer: two worklists (`instList` for non-artifacts, `artifactList` for `pseudo.merge`/`pseudo.unmerge`), bottom-up initial population (LIFO pop), alternating drain — legalize each non-artifact via `Target.LegalizerInfo`, then run the file-private `LegalizationArtifactCombiner` over each artifact, repeating until empty. An `IMirObserver` wired into the builder routes builder-driven insertions to the right worklist; an `IsTriviallyDead` check at the top of each step gives DCE for free. e.g. MOS6502 legalizes `arith.addi i32` → 4× `arith.addi_with_carry i8` with the surrounding `pseudo.merge` / `pseudo.unmerge` collapsed by the combiner.
    3. `InstructionSelectorPass` — selects target opcodes via `Target.InstructionSelector`. Calls `MirFunction.ReclassifyVirtualRegister` when committing a vreg to a class; emits `pseudo.copy` into pinned physregs (e.g. `$a`, `$c`) where the target opcode requires a specific physreg. Lowers `pseudo.return` to the target's return op (e.g. `mos6502.rts`) with the live-out return physregs as implicit uses.
    4. `PhiEliminationPass` — for each terminator carrying `BlockTarget.Args`, emits per-edge `pseudo.copy` from each arg to the successor's corresponding parameter vreg (breaking cycles with a temp). Splits multi-successor edges feeding parameterized blocks into single-successor split blocks first; because this runs post-isel, a split block's unconditional branch comes from `Target.BranchLowering` (e.g. `mos6502.jmp.abs`) rather than a generic `cf.br`. After this pass: every `BlockTarget.Args` is empty and no `MirBlock.Parameters` remain.
    5. `TwoAddressInstructionPass` — for each instruction whose `DialectInstructionInfo` declares tied def/use operands, emits a `pseudo.copy` to materialize the tied use as a copy of the def-source so RA can pick a single physreg for both ends.
    6. `RegisterAllocatorPass` — **graph-colouring** register allocation with iterated register coalescing (Chaitin/Briggs/George–Appel; Appel ch. 11). The wired `MirFunctionPass` is just the IR-facing wrapper: it builds `LiveIntervals`, drives the spill loop, and applies the vreg→physreg map (then clears the vreg annotation table and recomputes block live-ins). The colouring engine is the `internal` `GraphColouringAllocator` it instantiates (Build/Simplify/Coalesce/Freeze/SelectSpill/AssignColors). A node's colours are its **class-intersection's** allocatable set (per-node K), so no class-widening pre-passes are needed; coalescing handles constraint fix-up, result preservation and copy hints. Spilling: optimistic colouring, then `SpillVregs` rewrites true select-failures via rematerialization or store/reload (fresh temps marked unspillable; convergence-bounded re-colouring loop).
    7. `CopyEliminationPass` — drops identity `pseudo.copy $r → $r` and chases through trivially redundant chains. Operates on physreg-only MIR.
    8. *Target-supplied post-RA passes* — added by `Target.AddPostRegisterAllocationPasses(pm)`. For MOS6502: `MOS6502AddressingModeSelectorPass` (refines `mos6502.cmp` → `mos6502.cmp.zp` / `.imm` and `mos6502.st.abs` → `sta/stx/sty.abs` based on concrete physreg operands; adc/sbc are *not* handled here — the selector picks their concrete addressing-mode form directly). `Target.AddFinalPasses(pm)` then runs (after RegisterScavenging) `MOS6502BlockPlacementPass` (fall-through layout). Finally the driver runs the generic `TailDuplicationPass` — the llvm-mos `tailduplication` analogue that rebalances trivial shared return tails left by `ReturnMergePass`/the branch-folder: it clones a lone `rts` back into the predecessors that still branch to it (cost limit ≤1 instr, mirroring `TailDuplicator::shouldTailDuplicate` at -Os). Like LLVM's `TailDuplicator` it is target-agnostic and routes the few target questions through hooks — `Dialect.IsReturn` (MCInstrDesc::isReturn), `BranchLowering.TryGetUnconditionalBranchTarget` (the unconditional arm of analyzeBranch), `Dialect.IsTerminator`. It runs *after* block-placement — unlike llvm-mos's standalone pre-placement pass — because our block-placement lacks integrated tail-dup, so by then only the branches placement couldn't turn into free fall-throughs remain (running before placement would clone over jmps about to be dropped, growing code — caught by the `OutOfRangeBranch` byte-size golden).
    9. `PseudoExpansionPass` — replaces every remaining `pseudo.copy` with the target move emitted by `Target.PseudoExpander` (e.g. `$x = pseudo.copy $a` → `mos6502.tax`).
    - `Analyses/LivenessAnalysis` produces a `Liveness` result consumed by RA.
  - `Target/` — generic target abstractions: `Target` (exposes `Dialect`, `CallLowering`, `LegalizerInfo`, `InstructionSelector`, `PseudoExpander`, `BranchLowering`, `RegisterInfo`, `MachineCodeEmitter`, `GetRegisterName`, `AddPostRegisterAllocationPasses`, `DefaultOrigin`, `PackageImage`), `CallLowering`, `LegalizerInfo`, `InstructionSelector`, `PseudoExpander`, `BranchLowering` (supplies the target's unconditional jump for critical-edge split blocks created post-isel by `PhiEliminationPass`; mirrors LLVM's `TargetInstrInfo::insertUnconditionalBranch`), `TargetRegisterInfo`, `MachineCodeEmitter` (driver-called hook that lowers a post-PseudoExpansion `MirModule` to a `MachineCodeModule`).
  - `MachineCode/` — low-level machine-code layer; sits below MIR, above raw bytes
  - `Target/MOS6502/` — 6502 target
    - `MOS6502Registers` — physical register IDs: `a=0, x=1, y=2, s=3, p=4, c=5, n=6, v=7, z=8, i=9, d=10, b=11`; `RC(n) = 12 + n` for imaginary zero-page registers, printed as `$zp0, $zp1, …` (RC0/RC1 reserved as soft stack pointer per CC_MOS). `Home(n) = 300 + n` are the function-local zero-page **homes** (`$h0, $h1, …`): the allocator's pool for values that live across calls or overflow RC2..RC17. A home has no address until `MOS6502ProgramLayoutPass` places each function's block of homes in the target's zero-page window (BBC `$14–$8F`, C64 `$16–$8F`) above the blocks of all its callees (`StaticFrameColorer` over `CallGraph`; SCCs of the call graph share one block) and rewrites it to the `RC(n)` of its address, so a call never clobbers a live home and nothing is saved around calls. `MOS6502RecursionSavePass` (just before it) saves live homes with `PHA`/`PLA` around calls that stay inside the caller's SCC (recursion, and vtable/delegate calls that lead back). `CallGraph` (`Passes/Analyses`) sends an indirect call (including `jsr @__call_indirect_trampoline`, whose target pair is RC16/RC17) to every *address-taken* function only. The ABI window RC0..RC19 is fixed (soft stack pointer, arguments, RC18/19 pointer scratch); no register is callee-saved. Zero page overflow is a `NotSupportedException` (a `Diagnostic` from `CompilerDriver`); frame slots, which have an absolute fallback, are demoted to absolute memory first.
    - `MOS6502CallLowering` — CC_MOS convention: i8 bytes assigned in order A, X, RC2, RC3, … (LSB-first for multi-byte values).
    - `MOS6502LegalizerInfo` — declares `arith.addi i32 → NarrowScalar` (4× `arith.addi_with_carry i8`), `arith.addi i16 → NarrowScalar` (2× chain), etc.
    - `MOS6502InstructionSelector` — maps `arith.*` to target opcodes; fuses `arith.cmpi` + `cf.cond_br` into `mos6502.cmp` + `mos6502.bXX`; folds a single-use absolute-symbol load feeding an add/sub into the ALU's memory operand (`adc.abs`/`sbc.abs @sym`, dropping the `lda.abs`; mirrors llvm-mos `m_FoldedLdAbs`); lowers `pseudo.return` to `mos6502.rts`.
    - `MOS6502AddressingModeSelectorPass` — target-private post-RA pass; pattern-matches `mos6502.cmp` / `.st.abs` / `.lda` etc. against their concrete physreg / immediate operands and rewrites the opcode. (adc/sbc are excluded — the instruction selector emits their concrete `.zp` / `.imm` / `.abs` form directly, since the choice follows from the operand kind, not the RA-assigned register.)
    - `MOS6502PseudoExpander` — expands `pseudo.copy` to target moves (`mos6502.tax`, `.tay`, `.txa`, `.tya`, `.stx`, `.sty`, `.lda.zp`, `.ldx.zp`, `.ldy.zp`, `.lda.imm`, …). Impossible pairs (e.g. `$x = pseudo.copy $y`) expand via `$a`.
    - `MOS6502C64Target` — Commodore 64 subtarget (`--target mos6502-c64`, registry id `c64`): `DefaultOrigin` $080D, `ZeroPageBase` 2 (RC0/RC1 must not land on the 6510 port at $00/$01), $70–$8F static-frame window, `PackageImage` → `C64PrgImage` (`.prg` with a `10 SYS` BASIC stub), `c64_kernal` calling convention. CoreLib half: `DotNetro.CoreLib.C64` (`Console.C64.cs` PETSCII via KERNAL `$FFD2`/`$FFCF`). The test emulator is `--target-system c64`; every `.cs` lit test also has a `RUN-emulated-c64` line. See `notes/c64-plan.md`. The playground runs it in the EmulatorJS VICE core (`panels/c64Machine.ts`, unpacked at build time by `scripts/c64Core.ts`).
    - `MOS6502BbcMicroTarget` — subtarget inheriting from `MOS6502Target`; overrides only `DefaultOrigin` ($2000) and `PackageImage` to wrap raw bytes in a single-file Acorn DFS `.ssd` disk image via `BbcMicroDfsImage`.
    - Flag registers are first-class physregs: `mos6502.cmp` defines `$n`, `$v`, `$z`; `mos6502.bgt` reads them. `pseudo.copy` is never used for flag regs.

- **Libcalls** — `Target/MOS6502/libcalls.s`, hand-written MOS6502 assembly (embedded resource, parsed at use by `MOS6502AssemblyParser` with the target's `ZeroPageBase`, where `__rcN` names imaginary register N): `__mulhi3/__mulsi3/__muldi3`, the divide/remainder family (`__udivsi3`, `__divsi3`, `__umodsi3`, `__modsi3` and the `di3` forms) and the variable-count shifts (`__ashl/__lshr/__ashr` × `hi3/si3/di3`) that `MOS6502LegalizerInfo` lowers `arith.muli`/`*divi`/`*remi` and non-constant shifts to. They follow CC_MOS (arguments and results in A, X, `__rc2`…; free to clobber A/X/Y/flags/`__rc2..__rc19`; preserve `__rc0/1` and `__rc20..31`, saving any they use on the hardware stack). `Target.EmitProgram(MirModule)` emits the post-pipeline module and links in (`MachineCodeLinker`) the routines it references and does not already define, transitively; `Target.BuildProgram(module, origin)` also encodes it. Use these (as `iriec --emit=bin`, `CompilerDriver` and `irie-exec` do) rather than `MachineCodeEmitter.Emit` for anything that will run; `--emit=asm`/`mc` use plain `Emit`, so listings show only the program's own functions. `Lit/CodeGen/MOS6502/Libcalls-Exec.irie` runs every routine against the interpreter.

- **Irie.Tools.Compiler** — console app (`iriec`); reads MIR text (stdin or file), runs the full pass pipeline (AbiLowering → Legalizer → InstructionSelector → PhiElimination → TwoAddressInstruction → RegisterAllocator → CopyElimination → target-supplied post-RA passes → PseudoExpansion); `--target mos6502` / `--target mos6502-bbcmicro` (both share the same chip lowering; the BBC Micro variant only differs in `--origin` default and image packaging); `--stop-after` / `--start-at` / `--run-pass` for per-pass debugging; `--emit=mir` (default — post-pipeline MIR text) / `--emit=asm` (MOS6502 assembly text via `MachineCodeEmitter`) / `--emit=mc` (structured MachineCode binary to stdout, pipeable into `irie-mc --disassemble`) / `--emit=bin` (raw bytes via `MOS6502BinaryEncoder`, then wrapped by `Target.PackageImage` — e.g. an `.ssd` for `mos6502-bbcmicro`); `--origin=<hex|decimal>` (accepts `0x1900`, `0X1900`, `$1900`, or decimal) sets the load address, falling back to `target.DefaultOrigin`.

- **Irie.Tools.Interpreter** — reference interpreter for pre-pipeline (generic-dialect) MIR (`MirInterpreter.Call(function, args)`); the oracle for execution checks. Library only for now (no CLI). **Irie.Tools.Exec** (`irie-exec`) — takes a `.irie` file and `--exec "name(args)"` arguments, runs each function over generated inputs in the interpreter and, compiled with a generated driver, in the emulator (`--target`, as for `iriec`, only `mos6502-bbcmicro` so far; `--emulator <path>`), and fails on any mismatch. Used by `RUN-exec:` lines in the `LlvmMosReference` lit tests.
